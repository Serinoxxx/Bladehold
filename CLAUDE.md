# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Unity 6 game project, codenamed **Bladehold**. A 3D action game built on Unity's Universal Render Pipeline (URP) with the new Input System and NavMesh-based AI. The player fights waves of melee goblins, earns gold, and dies/restarts. Unity Editor version is pinned in `ProjectSettings/ProjectVersion.txt` (currently `6000.3.10f1`) — open with exactly this version.

## Building, running, and testing

There is no command-line build script. Day-to-day work happens in the Unity Editor:

- **Open the project**: open the project folder in Unity Hub with the matching Editor version.
- **Play / run**: enter Play mode in the Editor. The actual gameplay scene is `Assets/Bladehold/Bladehold Scenes/Bladehold Test Scene.unity` (renamed/moved 2026-07-08 from the vendored Synty `Demo_01_Sidekick.unity` sample — same scene GUID, contains `WaveSpawner`, the Player prefab instance, HUD canvas, and baked NavMesh). `ProjectSettings/EditorBuildSettings.asset` still points at the old, now-deleted `Assets/Scenes/SampleScene.unity` and needs re-pointing at the new scene in File > Build Profiles.
- **Build a player**: File > Build Profiles / Build Settings. URP renderers are pre-configured for two targets — `Assets/Settings/PC_Renderer.asset` and `Assets/Settings/Mobile_Renderer.asset`.
- **Tests**: `com.unity.test-framework` is installed. Run via the Editor's **Test Runner** window (Window > General > Test Runner). There are no test assemblies in `Assets/` yet — a new one needs its own `.asmdef` to be picked up.

The `.csproj` and `.slnx` files are **generated by Unity** for IDE integration (Rider / Visual Studio). Do not hand-edit them; edit code under `Assets/` and let Unity regenerate. C# compiles automatically on focus/save in the Editor.

## Source control

**Commit and push directly to `main`.** This is a solo project — do not create feature branches or open PRs unless explicitly asked. When the user says "commit and push" (or similar), commit straight onto `main` and push to `origin/main`.

## Code layout

First-party game code lives **only** in `Assets/Bladehold/Bladehold Scripts/` (note the space in the folder name), organized into subfolders: `Player/`, `Enemies/`, `DamageSystem/`, `Economy/`, `Chests/`, `Save/`, `UI/`, `Waves/`, `Stats/`, `Upgrades/`, `Reincarnate/`, `Analytics/`, plus `Editor/` for editor-only tooling (compiled out of builds by Unity's special-folder rule). Designer-editable data that isn't a `ScriptableObject` lives in `Assets/Bladehold/Config/` (`SkillTree.csv`, `Reincarnate.csv`, `Enemies.csv`). All first-party scenes live in `Assets/Bladehold/Bladehold Scenes/` (currently `Bladehold Test Scene.unity`, the real gameplay scene, and `SkillTreePreview.unity`) — new scenes go here, not under the old `Assets/Scenes/` (removed) or a vendored sample's folder.

Everything else under `Assets/` is vendored and should generally **not** be modified:
- `Assets/Third Party/` — Synty animations (incl. the **active player movement controller**, see below), Unity StarterAssets (present but **not** the controller in use), Wingman (editor tool), Kevin Iglesias animations.
- `Assets/LeanTween/`, `Assets/DamageNumbersPro/`, `Assets/Feel/` (MoreMountains Feel/Feedbacks — `MMF_Player`), `Assets/AssetInventory/` — vendored asset-store packages used by game code.

There are **no `.asmdef` files for game code**, so all first-party scripts compile into the default `Assembly-CSharp`. The only first-party-adjacent assembly definition is `Assets/Third Party/Wingman/Wingman.asmdef` (an editor productivity tool, not game logic).

## Architecture

Gameplay centers on the player fighting waves of melee goblins. The design leans heavily on **`ScriptableObject` config**, **event-driven decoupling**, and a few **scene singletons**. The most important idea to internalize is the `Health` event model (see Conventions) — almost every system hangs off it.

> **This doc lags the code. Treat it as a map, not an inventory.** The sections below go deep on some systems and are silent on others that exist — so **do not infer that a feature is absent because it isn't described here.** For any "does X exist / how does X work" question, `grep` under `Assets/Bladehold/Bladehold Scripts/` **first** and trust the code over this file.

### Player (`Player/`)
> **Movement controller:** the player uses the vendored **`Synty.AnimationBaseLocomotion.Samples.SamplePlayerAnimationController`** (`Assets/Third Party/Synty/AnimationBaseLocomotion/Samples/Scripts/`), **not** Unity StarterAssets' `ThirdPersonController`. It drives a `CharacterController`, reads input through Synty's **`InputReader`** (which exposes `onAttackActivated`/`onAttackDeactivated` press/release events plus aim/sprint/crouch/etc.), and derives per-gait movement from the **private** `_walkSpeed`/`_runSpeed`/`_sprintSpeed` fields. Attack animation is driven by the `StartAttack` trigger + `IsHoldingAttack` bool. Neither Synty nor StarterAssets has an `.asmdef`, so these types are reachable from `Assembly-CSharp` (first-party code references them directly; `PlayerMoveSpeedBinder` reaches the private speed fields by reflection rather than editing vendored source).

- **`Player`** (`Player.cs`) — singleton (`Player.Instance`, set in `Awake`). Caches and exposes the player's `Health`, `IDamageable`, `Wallet`, and **`PlayerStats`**. Everything locates the player through this static reference rather than scene lookups.
- **`PlayerDeath`** (`PlayerDeath.cs`) — on `Health.OnDied`, disables an inspector-assigned list of control components (movement/input, kept decoupled from the vendored controller by type) and fires a `Death` animator trigger. Does **not** run if `DeathNova` cancels the death first (see below) — `OnDied` never fires for that hit.
- **`AnimationEvents`** (`AnimationEvents.cs`) — receiver for Unity animation events on the player rig; e.g. `OneHandedSwordAttack()` activates the sword's `DamageTrigger` at the right animation frame, and `PlaySwordWoosh()` (called earlier in the swing) plays the swing sound via `SwordHitFeedback`.
- **`SwordChargeFeedback`** (`SwordChargeFeedback.cs`) — escalating charge-up feedback. Polls `PlayerAttack.IsCharging`/`ChargeLevel` (same style `PlayerMoveSpeedBinder` polls stats) and plays the next `MMF_Player` in an inspector-assigned array each time the hold gains another charge level (stage N plays at level N+1; levels beyond the array keep the last stage's look).
- **`VampiricBlade`** (`VampiricBlade.cs`) — gold-tree skill line. Listens to the sword `DamageTrigger.OnHit` (the `SwordHitFeedback` pattern) and heals the player `StatType.LifeStealPercent` × damage dealt via `Health.Heal`. The sword trigger must be assigned explicitly (no auto-wire — the player has other `DamageTrigger`s like the nova hitbox). Base 0 = locked.
- **`DamageBlocker`** (`DamageBlocker.cs`) — the "Solid" gold-tree skill line. Hooks `Health.TryBlockDamage` on the player's `Health` and negates one incoming hit every `StatType.BlockCooldown` seconds (base 0 = locked; the first node sets 10s, later tiers subtract). Optional block `MMF_Player` feedback.
- **`Parry`** (`Parry.cs`) — the "Parry" gold-tree skill line, a directional sibling of `DamageBlocker`: also hooks `Health.TryBlockDamage`, but rolls `StatType.ParryChance` on every hit (no cooldown) and only succeeds while the player is facing the attacker (dot product of `transform.forward` vs. the direction to `Damage.sourcePosition` against a serialized `facingDotThreshold`). Only "melee" hits (`DamageType.sharp`/`blunt`) are parryable — `elemental` hits (Storm Witch) always pass through, as does any hit stamped `Damage.unparryable` (e.g. the Troll's ground slam, a wide AoE with no single swing to read). Raises `event Action<Damage> OnParried` for reactive add-ons rather than knowing about them itself. Base 0 = locked.
- **`Counterstrike`** (`Counterstrike.cs`) — the "Counterstrike" gold-tree skill line, layered on `Parry` the way `VampiricBlade` is layered on the sword's `OnHit`: listens to `Parry.OnParried` and deals `StatType.CounterstrikePercent` of effective sword damage (`SwordDamage × AllDamageMultiplier`) back to `Damage.source` (the attacker's own `IDamageable`, if the hit carried one). Base 0 = locked — Parry alone still blocks, just without payback.
- **`AttackCancelsSprint`** (`AttackCancelsSprint.cs`) — pressing attack always cancels sprinting (independent of any skill-tree state; the "Sprinter" nodes just raise `StatType.SprintSpeed`). Subscribes to `InputReader.onAttackActivated` and invokes the controller's private `DeactivateSprint()` by cached reflection (the `PlayerMoveSpeedBinder` precedent) — the method rather than the `_isSprinting` field, since it also restores strafe state. Sprint stays off until the player presses sprint again.
- **`DeathNova`** (`DeathNova.cs`) / **`DeathNovaSO`** — Reincarnate-tree ability. Hooks `Health.TryPreventDeath` on the player's own `Health`; if unlocked (`StatType.DeathNovaCharges >= 1`) and off cooldown, it activates a `DamageTrigger` child hitbox (damage + knockback on nearby enemies) on every lethal hit, then — only if `StatType.DeathNovaRevivePercent > 0` — calls `Health.Revive` and cancels the death. The base node is blast-only; a separate stacking Reincarnate node adds the revive.
- **`GoldOnDeathCollector`** (`GoldOnDeathCollector.cs`) — Reincarnate-tree ability ("Grave Robber"). On the player's real `Health.OnDied` (i.e. death that `DeathNova` didn't cancel), auto-collects `StatType.GoldOnDeathPickupPercent` of the gold currently on the ground into the `Wallet`.
- **`ImpulseBuff`** (`ImpulseBuff.cs`) / **`ImpulseSO`** — gold-tree ability ("Impulse"). A timed, orb-stacked buff: each `ImpulseOrb` pickup adds `StatType.ImpulseOrbDuration` seconds and a stack (all stacks expire together), registers the `ImpulseOrbDuration`/`ImpulsePower` stat bases in `Start` (base 0 = locked until the `impulse_unlock` node), and exposes `IsActive`/`StackCount`/`DamageMultiplier`/`CurrentImpulsePower`/`CurrentImpulseForce`/`PowerPerChargeLevel`/`OnChanged` for `DamageTrigger` and cosmetic listeners (activation/deactivation `MMF_Player`s, a looping aura child) to read.

### Damage system (`DamageSystem/`) — the combat core
- **`IDamageable` / `Damage` / `DamageType`** (`Damageable.cs`) — the damage interface (`ReceiveDamage(Damage)`), the damage payload (`value`, `type`, plus `impulsePower`/`impulseForce` — the Impulse buff's fling rating and launch speed, stamped by `DamageTrigger`, 0 = no impulse on this hit — `source`, the attacker's own `IDamageable` when the hit came from a single identifiable enemy, e.g. `AIAttack`/`TrollSlamAttack` stamping their own `Health`, used by `Counterstrike` to hit back — and `unparryable`, set by `TrollSlamAttack` so its ground slam can't be blocked by `Parry`), and the type enum (`sharp`/`blunt`/`elemental`).
- **`Health`** (`Health.cs`) — implements `IDamageable`. Holds `currentHealth` initialized from a `HealthSO`. Raises **`OnDied`** once when health first hits zero (latches via `IsDead`; further damage ignored) and **`OnDamaged(Damage)`** on every hit. Plays an `MMF_Player` damage feedback. Before latching, it checks **`TryPreventDeath`** (an `event Func<bool>`) — a handler that returns `true` (e.g. `DeathNova` revivifying the player via `Revive(amount)`) cancels the death outright, so `OnDied` never fires for that hit. At the very top of `ReceiveDamage` it similarly checks **`TryBlockDamage`** (an `event Func<Damage, bool>`) — a `true` handler (e.g. `DamageBlocker`'s "Solid" auto-block) negates the hit entirely: no health loss, no feedback, no events. Also exposes **`Heal(amount)`** (clamped to `MaxHealth`, ignored while dead — used by `VampiricBlade` lifesteal). Health knows nothing about what reacts to these events.
- **`HealthSO`** — `maxHealth`. **`DamageSO`** — `baseDamage`, `isCritical`. **`DamageTriggerSO`** — `radius`, `duration`, `maxHits`.
- **`DamageTrigger`** (`DamageTrigger.cs`) — an activatable hitbox with two `detectionMode`s. `Activate()` (called from an animation event) opens it for `duration`; each `FixedUpdate` while active it detects hits, applies `DamageSO`/stat-driven damage, dedupes targets with a `HashSet`, and **never damages its owner** (the nearest `IDamageable` up the parent hierarchy, or an explicit `owner`). **`Sphere`** mode (the default, used by e.g. the Death Nova blast) `OverlapSphere`s `damageTriggerSO.radius` around the trigger's own position — unchanged from before. **`BladeSweep`** mode (the sword) samples `basePointCount` points along `bladeBase`→`bladeTip` and each tick raycasts every point from its *previous* position to its *current* one, so a fast/long swing can't tunnel past a thin collider between frames. In both modes, the effective cut-through cap is `StatType.MaxHitsPerSwing` when `readsPlayerStats` is on (else `damageTriggerSO.maxHits`); reaching the cap no longer ends the activation early — it keeps sweeping for the full `duration`, and only the *next new* target beyond the cap cancels it: no damage is applied to that target, `OnBlocked` fires, and the activation ends immediately. Every other successful hit raises `OnHit(IDamageable, Damage, Vector3 hitPoint)`. When `readsPlayerStats` is on, `StatType.SwordRange` is a unitless multiplier (base 1.0, same convention as `MoveSpeed`) that both scales `basePointCount` for that swing and — via an `OnStatChanged` subscription — the sword's own `transform.localScale`, so upgrading range visibly lengthens the blade. While the player's `ImpulseBuff` is active, `BuildDamage()` also stamps `Damage.impulsePower` (buff power + charge level × `powerPerChargeLevel`) and `Damage.impulseForce` (buff launch speed × `1 + chargeLevel × ChargeKnockbackBonus` — impulse is knockback-flavoured, so Amplified Knockback boosts both) onto every hit, and multiplies `value` by the buff's per-stack `DamageMultiplier`.
- **`SwordHitFeedback`** (`SwordHitFeedback.cs`) — reacts to the sword's `DamageTrigger.OnHit`/`OnBlocked` the same way `DamageNumberSpawner` reacts to `Health.OnDamaged`: plays a cutting sound (a distinct pool on crits) and spawns a blood-particle burst at the hit point, sized and sped up with damage up to a cap; on `OnBlocked`, fires a `Blocked` animator trigger. Also exposes `PlayWoosh()` for the swing's animation event.
- **`DamageNumberSpawner`** (`DamageNumberSpawner.cs`) — listens to `Health.OnDamaged`, spawns a DamageNumbersPro popup that follows the target; uses an alternate `critPopupPrefab` instead of the normal one when the hit was critical, if one is assigned.
- **`DisableCollidersOnDeath`** (`DisableCollidersOnDeath.cs`) — listens to `Health.OnDied`, disables all child colliders so a corpse stops blocking/absorbing hits.
- **`CorpseDespawner` / `CorpseManager` / `CorpseConfigSO`** (`CorpseDespawner.cs`, `CorpseManager.cs`, `CorpseConfigSO.cs`) — corpse cleanup so long runs can't accumulate unbounded scene weight. `CorpseDespawner` (on each enemy prefab; a normal `Health.OnDied` listener) freezes the corpse's Animator after `animatorDisableDelay`, then sinks the corpse and destroys it after `corpseLifetime` (0 = no timer). `CorpseManager` is an optional scene **singleton** enforcing `CorpseConfigSO.maxCorpses`: corpses register on death, and the oldest is told to `DespawnNow()` when the cap is exceeded; with no manager present each corpse just runs its own timer. All timings on `CorpseConfigSO`. `CorpseDespawner` also exposes `event Action OnDespawnStarted`, raised once the sink actually begins (timer or early cap-despawn) — `EnemyRagdoll` subscribes to freeze a still-simulating ragdoll before the sink carries its (now-kinematic) bones down with the root.
- **`RagdollConfigSO`** (`RagdollConfigSO.cs`) — physical build tunables for the runtime ragdoll (layer name, total mass 40, damping, limb/head/torso sizing ratios, CharacterJoint limits, max depenetration velocity). **`ImpulseConfigSO`** (`ImpulseConfigSO.cs`) — the enemy/reaction-side gameplay tunables for the Impulse fling (`defaultResistance`, launch angle/spin, settle/timeout windows, NavMesh recovery retry/timing, `getUpSeconds`/`knockdownSeconds`, `maxSimultaneousRagdolls`); the player-side buff numbers live on `ImpulseSO` instead.
- **`EnemyRagdoll`** (`EnemyRagdoll.cs`) — lazy runtime ragdoll builder. Enemy prefabs carry no ragdoll bones; the first time an enemy is flung, `BuildIfNeeded()` walks the Humanoid rig via `Animator.GetBoneTransform` and adds 11 Rigidbodies/CharacterJoints/colliders sized from the actual bone lengths (so scaled enemies like the brute just work), then idles kinematic with colliders disabled — built bodies are reused on later flings, so un-flung enemies cost nothing. Exposes the static `ActiveCount` (the horde cap `ImpulseReceiver` checks against `ImpulseConfigSO.maxSimultaneousRagdolls`) plus `EnterRagdoll`/`AddImpulse`/`ExitRagdoll`/`FreezeCorpse` and the `Pelvis` reference used for landing/recovery.
- **`ImpulseReceiver`** (`ImpulseReceiver.cs`) — reacts to impulse-stamped hits on an enemy, the same `Health.OnDamaged` pattern as `KnockbackReceiver`. Against this enemy's impulse resistance `r` (per-type via the roster CSV's `impulseResistance` column, applied through `SetResistance`; else `ImpulseConfigSO.defaultResistance`): `power >= r` triggers a full ragdoll fling state machine (Normal→Airborne→Recovering, handing bones to `EnemyRagdoll`, then NavMesh re-seat + get-up on landing if still alive), `power >= r-1` triggers an animation-only `KnockedDown` state, below does nothing extra. A landing that never finds the NavMesh force-kills the enemy through `Health.ReceiveDamage` so wave/coin/kill accounting stays consistent; flings beyond the horde cap degrade to knockdowns. Exposes `State`/`IsIncapacitated`/`WouldIncapacitate(Damage)` so `KnockbackReceiver` can skip its slide on the same hit.
- **`ImpulseHitFeedback`** (`ImpulseHitFeedback.cs`) — sibling of `SwordHitFeedback`: reacts to the sword `DamageTrigger.OnHit`, and for any hit carrying `Damage.impulseForce > 0` spawns a particle burst and a pulsing point light at the hit point, both scaled by impulse force up to a cap. `damageTrigger` is an explicit assignment (no auto-wire — the VampiricBlade precedent).

### Enemies (`Enemies/`)
- **`AIMovementSO`** — pathfinding (`speed`, `updateInterval`), gait speeds (`walkSpeed`/`runSpeed`/`sprintSpeed`, used to derive blend thresholds), optional `leanCurve`, plus the horde-scaling performance knobs consumed by `AIMovement`/`AIAnimation` (near/far avoidance tiers + `farDistance`, avoidance-priority jitter range, `farRepathInterval`, `cullOffscreenAnimators`, `animationFullRateDistance`, `animationFarFrameInterval`).
- **`AIMovement`** (`AIMovement.cs`) — drives a `NavMeshAgent` to chase `Player.Instance`, re-issuing `SetDestination` only every `updateInterval` seconds (staggered by a random initial offset so hundreds of agents never repath in lockstep; agents beyond `farDistance` repath at the slower `farRepathInterval`). Applies the SO's avoidance settings in code so the prefab's `NavMeshAgent` stays untouched: a random `avoidancePriority` per agent, `nearAvoidance` quality inside `farDistance`, `farAvoidance` (default none) beyond it — full N-body avoidance only matters in the dense ring around the player. Stops on its own `Health.OnDied` (also disabling itself and the agent — corpses don't tick) and on the player's death.
- **`LocomotionAnimator`** (`LocomotionAnimator.cs`) — plain (non-`MonoBehaviour`) reusable class extracted from Synty's `SamplePlayerAnimationController`. Computes locomotion blend params (`MoveSpeed`, `CurrentGait`, strafe/shuffle, `LeanValue`, …) from a per-frame `LocomotionInput` and writes them to an `Animator`. Input-agnostic; never moves the transform.
- **`AIAnimation`** (`AIAnimation.cs`) — maps a goblin's `NavMeshAgent` motion onto `LocomotionAnimator.LocomotionInput` each frame. Fires a `Death` trigger on death (then disables itself — corpses don't tick) and a `Cheer` trigger when the player dies. Two horde-scaling behaviours from `AIMovementSO`: sets the Animator to `CullUpdateTransforms` (off-screen enemies skip skeleton/skinning but the state machine keeps running, so triggers never pop — never use `CullCompletely`), and beyond `animationFullRateDistance` ticks locomotion only every `animationFarFrameInterval`th frame (staggered per enemy, passing the **accumulated** deltaTime since `LocomotionAnimator`'s damping is deltaTime-dependent).
- **`AIAttackSO`** / **`AIAttack`** (`AIAttack.cs`) — melee attack. When the player is within `attackRange` and off cooldown, fires an `Attack` animator trigger; after `windupToApex` seconds, if the player is still alive and in range, applies damage. Never touches the `NavMeshAgent`, so goblins attack while chasing.
- **`EnemySO`** / **`CoinDropper`** (`CoinDropper.cs`) — on `Health.OnDied`, drops a `Coin` pickup worth a rolled amount from `EnemySO` (or a per-instance `SetCoinDrop` override from the enemy roster CSV).
- **`EnemyRosterSO` / `EnemyDefinition`** (`EnemyRosterSO.cs`) — the enemy-type roster, parsed from `Config/Enemies.csv` (same designer-edits-a-spreadsheet pattern as `SkillTreeSO`; both share `CsvUtil.SplitLine`). Columns: `id,displayName,health,damage,minGold,maxGold,speed,scale,unlockWave,spawnChance,minSpawn,maxConcurrent,impulseResistance`. The stat columns are **optional overrides** — blank keeps the prefab's own SO value; the shared SOs are never mutated. The **first row is the unlimited fallback type** (goblin); later rows carry `unlockWave` (first wave they can appear), `spawnChance` (per-spawn roll, authored as a **percent**: 10 = 10%), `minSpawn` (the per-wave spawn **budget** at the unlock wave — both a guarantee filled before any chance rolls *and* a per-wave cap; it grows by one each wave after unlock, capped at `maxConcurrent` when set, so brutes with `minSpawn 1`/`maxConcurrent 3` appear 1, 2, 3, 3, … per wave; blank/0 = chance-only, no cap), and `maxConcurrent` (max alive at once, blank/0 = unlimited). `Health`/`AIAttack`/`CoinDropper`/`AIMovement` each expose a per-instance setter (`SetMaxHealth`/`SetDamage`/`SetCoinDrop`/`SetSpeed`) that `WaveSpawner` calls right after `Instantiate`, before the instance's `Start` (the `MarkGolden` timing trick); `impulseResistance` is applied the same way via `ImpulseReceiver.SetResistance`.
- **`Enemy`** (`Enemy.cs`) — marks a GameObject as an enemy; on `Health.OnDied` reports the kill to `GameStats`.
- **`GoldenGoblin`** (`GoldenGoblin.cs`) — Reincarnate-tree ability. `WaveSpawner` rolls `StatType.GoldenGoblinChance` per spawn and calls `MarkGolden()` right after `Instantiate` (before `Start` runs). A golden goblin swaps to a gold material and, independently of `CoinDropper`, drops its own bonus `Coin` (worth `StatType.GoldenGoblinGoldBonusPercent` of a fresh `EnemySO` roll) plus optional VFX/SFX on `Health.OnDied`.
- **`ImpulseGoblin`** (`ImpulseGoblin.cs`) — GoldenGoblin mirror for the Impulse gold-tree ability. `WaveSpawner` independently rolls `StatType.ImpulseGoblinChance` per spawn and calls `MarkImpulse()` right after `Instantiate` (before `Start`). A marked goblin swaps to an aura material and always drops one `ImpulseOrb` on `Health.OnDied` (independent of `CoinDropper`), plus optional VFX/SFX. A goblin can be both golden and impulse (independent rolls) — `GoldenGoblin.ApplyGoldenVisual()` guards on `ImpulseGoblin.IsImpulse` so the impulse aura wins the body swap (it telegraphs combat behaviour; gold is economy-only), while both drops still occur.

### Economy (`Economy/`)
- **`GameStats`** (`GameStats.cs`) — per-run scoreboard **singleton** (`GoblinsKilled`, `GoldEarnedThisRun`). Lives in the scene, so it resets on scene reload. Raises `OnChanged`.
- **`Wallet`** (`Wallet.cs`) — the player's coin purse. Loads its total from disk (`SaveSystem`) on `Awake` and saves on every change, so gold **persists across runs**. Raises `OnCoinsChanged`.
- **`Coin`** (`Coin.cs`) — a pickup; on trigger-enter by the `Wallet` holder it deposits to the `Wallet` and `GameStats`, shows a popup, and destroys itself. Uncollected coins expire after a serialized `lifetime` (default 90s, 0 = never) so long fights can't pile up unbounded trigger colliders — generous enough that Grave Robber's gold-on-the-ground economy is essentially unaffected.
- **`ImpulseOrb`** (`ImpulseOrb.cs`) — dropped by a dying Impulse Goblin. On trigger-enter, grants buff time + a stack to the picker-upper's `ImpulseBuff` (found via `GetComponentInParent`), shows a popup with the seconds granted, and destroys itself. A deliberate sibling of `Coin` rather than sharing a base class; shorter default `lifetime` (30s) than a coin's, since a timed buff should feel urgent.
- **`HoldTheLineBonus`** (`HoldTheLineBonus.cs`) — the "Hold the Line" greed economy, a scene **singleton** (`Instance`). Choosing to skip the recovery intermission (see `WaveIntermissionUI`) calls `Extend()`, which banks one more consecutive-Hold stack by adding `StatType.HoldTheLineGoldPerWave` (base 5%, registered in `Start`) as a stacking `Percent` modifier on `StatType.GoldDropMultiplier` — so `CoinDropper` needs no changes (it already reads the multiplier fresh per kill; the "register upgradeable numbers as stats" convention). Owns the exact applied percent so `ResetBonus()` cancels it precisely (the `ImpulseBuff` add/remove idiom). **Both fail-states reset the streak**: the player's `Health.OnDied` and `Gate.OnAnyGateDestroyed`. Choosing "Recover" keeps the stack but doesn't grow it. Exposes `Multiplier`/`StackCount`/`OnChanged`; the per-wave amount is upgraded by the Reincarnate "Greedy Stand" node.

### Chests (`Chests/`)
Smashable loot chests scattered each wave. A chest is just a `Health` damage target — no bespoke combat code — so the sword hits it for free and the death event drives loot.
- **`Chest`** (`Chest.cs`) — listens to its own `Health.OnDied` (the `CoinDropper`/`LightningOrbDropper` convention) and drops **guaranteed gold** (a `Coin` via `SetAmount`) plus, on a roll, **one weighted bonus item** from its `ChestLootTableSO` (existing pickups: `HealthPack`/`LightningOrb`/`ImpulseOrb`/gold-bag). Per-hit and break juice live on the `Health`'s `damageFeedback`/`deathFeedback` `MMF_Player`s (Health plays them — no separate hit-feedback script), plus an over-the-top `breakVfxPrefab` spawned on death. Chests are **kinematic and carry no `ImpulseReceiver`/`KnockbackReceiver`**, so the sword's impulse fling never moves them; a health bar is just an `MMHealthBar` + `HealthBarUI` (the enemy pattern). The collider must sit on a layer inside the sword `DamageTrigger.hitLayers` mask.
- **`ChestLootTableSO`** (`ChestLootTableSO.cs`, `Scriptable Objects/ChestLootTableSO`) — per-tier loot: `minGold`/`maxGold` for the guaranteed `Coin`, plus a `bonusItemChance` and a weight-listed `items` roster (`RollGold()` / `RollBonusItem()` — single weighted pick, null when the bonus roll fails).
- **`ChestSpawner`** (`ChestSpawner.cs`) — on `WaveSpawner.WaveStarted`, scatters `min..maxPerWave` chests, each picked by weight from a per-level prefab list (`unlockWave`-gated), NavMesh-snapped and kept `minPlayerDistance` from the player (the `WaveSpawner` placement idiom). A pure spawner — it never tracks chest destruction.

### Save (`Save/`)
- **`SaveData`** (`SaveData.cs`) — `[Serializable]` snapshot of persisted progress: `totalGold`, `purchasedNodeIds` (gold tree, cleared on Reincarnate), `reincarnatePoints` and `purchasedReincarnateNodeIds` (Reincarnate tree — never cleared). Add fields here; old saves load missing fields as defaults.
- **`SaveSystem`** (`SaveSystem.cs`) — static JSON read/write under `Application.persistentDataPath`. Load is resilient (missing/corrupt file → fresh `SaveData`).

### Waves (`Waves/`)
- **`WaveConfigSO`** — wave-size and pacing tunables: `baseGoblinCount`, `goblinsAddedPerWave`, `maxConcurrent`, `timeBetweenWaves`, `spawnInterval`; `GoblinsForWave(n)` returns the total for wave `n`.
- **`WaveSpawner`** (`WaveSpawner.cs`) — **singleton** (`WaveSpawner.Instance`). Runs an endless countdown → spawn → clear → next-wave loop. Caps concurrent enemies at `maxConcurrent` and trickles in replacements (one per `spawnInterval`) as enemies die, until the wave's total has been killed. **What spawns comes from an `EnemyRosterSO`** plus an inspector list mapping each CSV `id` to a prefab (rows without a prefab mapping are skipped with a warning): each spawn slot first fills any type still under its per-wave budget (`PerWaveBudget`: `minSpawn` ramping +1 per wave since unlock, capped by `maxConcurrent` — see `EnemyRosterSO` above), then checks the non-fallback rows in CSV order and spawns the first that is unlocked, under its own per-type concurrent cap and budget, and wins its `spawnChance` roll — else the fallback first row (goblin). Roster stat overrides are applied to the instance right after `Instantiate` (see `EnemyRosterSO` above), including `impulseResistance` via `ImpulseReceiver.SetResistance`. Independently of the Golden Goblin roll, `WaveSpawner` also rolls `StatType.ImpulseGoblinChance` per spawn (base registered next to the Golden Goblin bases) and calls `ImpulseGoblin.MarkImpulse()` on a winning roll — a goblin can win both rolls. Snaps spawn positions to the NavMesh and keeps them at least `minPlayerDistance` from the player (re-rolling a few candidates, falling back to the farthest). Tracks each enemy's death via its `Health.OnDied` (enemies are corpses, not destroyed — see Conventions), decrementing the per-type live count. Stops on player death. Exposes `CountdownTick`/`WaveStarted`/`WaveCleared` events and `CurrentWave`. **Between-wave choice**: after each `WaveCleared`, `RunWaves` fires `IntermissionStarted` and parks on `WaitForPlayerChoice` until a UI calls `ChooseHoldTheLine()` (the next wave keeps its pre-wave countdown as a window to loot the cleared field — the greed reward) or `ChooseRecover()` (sets `skipNextCountdown` so the next wave lands immediately, since the player upgraded during the frozen intermission instead of looting; see `HoldTheLineBonus`/`WaveIntermissionUI`). The top-level `IntermissionChoice` enum carries the pending answer. **With no `IntermissionStarted` subscriber the spawner proceeds straight to the countdown**, exactly as before, so the game runs without the intermission UI. Dev cheats: `DebugWipeWave()` (instantly kills the wave in progress), `DebugSetNextWave(wave)` (overrides the wave that begins next — stored mid-wave and applied on clear, or retargets the countdown's upcoming wave during the intermission; `NextWave` exposes the effective value), and `DebugSpawnBurst(count)` (perf stress test — spawns extra enemies into the current wave, ignoring `maxConcurrent` and spawn pacing, sliced across frames; grows the wave total so normal kill accounting still clears it; wipe/burst are no-ops during the intermission), wired to DevConsole controls (Wipe Wave button; next-wave integer field with ▲/▼ arrows).
- **`WaveUI`** (`WaveUI.cs`) — listens to the spawner and drives a TMP canvas: "Wave starts in {n}", "BEGIN", "Wave Cleared!", plus an optional persistent "Wave {n}" label.
- **`WaveIntermissionUI`** (`WaveIntermissionUI.cs`) — orchestrates the between-wave beat off `WaveSpawner.IntermissionStarted`: plays a slow-mo `MMF_Player` (an MMF Timescale Modifier), then **hard-freezes time (`Time.timeScale = 0`)** so the player can't clean up loot while deliberating, reveals the stats (`WaveStatsPanel`, unscaled), and shows two choices — **"Recover and Upgrade"** (opens a skill-tree panel, still frozen = untimed shopping; a Continue button then unfreezes + calls `ChooseRecover()`) or **"Hold the Line"** (calls `HoldTheLineBonus.Extend()`, unfreezes + `ChooseHoldTheLine()`, so the pre-wave countdown becomes a loot window). Both commit paths route through `CloseIntermission` (unfreeze + re-lock cursor exactly once). Waits `slowMoRealSeconds` for the slow-mo to restore before freezing so the two don't fight over `Time.timeScale`. Keeps the wave loop parked while the skill tree is open (releases only on Continue). The spawner stays UI-unaware. **Intermission MMF feedbacks must use MMF's Unscaled time mode**, since they play while time is frozen. **`WaveStatsPanel`** (`UI/WaveStatsPanel.cs`) — snapshots the `GameStats` scoreboard on `WaveStarted` and, in `PlayReveal`, count-up-animates this wave's goblins/gold + total + the live Hold multiplier (unscaled), cascading lines with optional per-line `MMF_Player`s and bar wipes. A pure display.
- **`RunState`** (`RunState.cs`) — static `StartingWave`, the one piece of run state that must **survive a scene reload within a session** (statics persist across `LoadScene` but reset when play stops). The spawner keeps it at the current wave; the death screen sets it to 1 or the current wave to choose where a restart resumes.

### UI (`UI/`)
- **`CoinUI`** (`CoinUI.cs`) — binds a TMP label to the player's `Wallet.OnCoinsChanged`.
- **`DeathScreen`** (`DeathScreen.cs`) — fades in on player death (via `Player.Instance.Health.OnDied`), shows run stats and total gold, and offers two restarts: from wave 1, or from the wave the player died on (the optional current-wave button reads `WaveSpawner.Instance.CurrentWave` and sets `RunState`). Both reload the active scene. An optional third button calls `ReincarnateService.Instance.Reincarnate()` instead (see Reincarnate below), previewing the points via `PreviewPointsForReincarnate()`.

Navigation depends on a baked NavMesh in the scene (`com.unity.ai.navigation`); AI agents (and wave spawning onto the NavMesh) will not work without it.

### Stats & upgrades (`Stats/`, `Upgrades/`)
A CSV-driven skill tree, shown on the death screen, where gold buys branching, stackable upgrades. Built on a central stat layer so combat/movement code reads *effective* values without the underlying configs ever being mutated.
- **`StatType` / `ModifierKind`** (`Stats/StatType.cs`) — the shared vocabulary of modifiable stats (`SwordDamage`, `SwordRange`, `MaxHitsPerSwing`, `GoldDropMultiplier`, `MoveSpeed`, `SprintSpeed`, `CritChance`, `CritMultiplier`, `KnockbackForce`, `ChargeDamageBonus`, `ChargeKnockbackBonus`, `MaxChargeLevels`, `LifeStealPercent`, `BlockCooldown`, `ParryChance`, `CounterstrikePercent`, plus the Reincarnate-only `DeathNovaCharges`/`DeathNovaCooldown`/`DeathNovaRevivePercent`/`GoldenGoblinChance`/`GoldenGoblinGoldBonusPercent`/`GoldOnDeathPickupPercent`, and the Impulse gold-tree ability's `ImpulseGoblinChance`/`ImpulseOrbDuration`/`ImpulsePower`) and modifier kinds (`Flat`, `Percent`).
- **`PlayerStats`** (`Stats/PlayerStats.cs`) — the aggregation layer, reached via `Player.Instance.Stats`. Each stat is `final = (base + Σflat) × (1 + Σpercent)`. **Bases are registered at runtime** by whichever system owns the value (so the SOs/controller stay the source of base truth, never mutated); upgrades call `AddModifier`; consumers call `GetValue`. Raises `OnStatChanged`. Modifiers can be added before or after a base is set — order-independent. `MoveSpeed`/`SprintSpeed`/`SwordRange`/`GoldDropMultiplier` are unitless **multiplier** stats (base 1.0; `GoldDropMultiplier`'s base is registered by `WaveSpawner` next to the Golden Goblin stats and consumed by `CoinDropper`).
- **`SkillNode` / `SkillEffect` / `SkillTreeSO`** (`Upgrades/`) — `SkillTreeSO` (`Scriptable Objects/SkillTreeSO`) parses a designer-edited CSV `TextAsset` (columns `id,displayName,description,cost,stat,kind,amount,prereqs,x,y,icon,family`) into `SkillNode`s, currency-agnostic (`cost` is just an int — both the gold tree's `Config/SkillTree.csv` and the Reincarnate tree's `Config/Reincarnate.csv` use a `SkillTreeSO` asset each). Blank `stat` = connector/unlock-only node (`effects` empty). The trailing `icon` column is optional (absent column or blank cell = no icon) and names a sprite in the `SkillTreeSO` asset's serialized `icons` list — `SkillTreeSO.GetIcon(name)` resolves it, and `SkillNodeView` shows it in an optional `icon` Image (hidden when unresolved), so each tree asset maps CSV icon names to sprites in the inspector. `stat`/`kind`/`amount` may each be `;`-separated lists of equal length to apply several `SkillEffect`s atomically from one purchase (e.g. Golden Goblin tiers bump both a chance stat and a bonus-% stat together). `prereqs` is `;`-separated (blank = a root, visible from start). A link is **symmetric** — there's no arrow on the connector, so a node is revealed once *any* linked node is bought, whether that link is authored on this node's own `prereqs` or on the other node's (the reverse direction is resolved via `SkillTreeSO.GetDependents`). Duplicate effects across different ids are intentional — buying both **stacks**. The optional trailing `family` column puts same-type nodes (e.g. every "Extended Blade") into one **shared price ladder**: family nodes can be bought in any order, but the Nth family purchase costs the Nth-cheapest authored cost in the family, whichever node it's spent on — so scattering a family across the tree can't leak cheap late copies, and the per-node `cost` column doubles as the ladder's rungs (blank family = priced individually). Families whose node text states absolute values (Solid's "every N seconds", Critical Damage's "2x/4x/8x", Heavy Strike's charge levels) are still physically chained via prereqs so their descriptions stay truthful.
- **`ISkillTreeService`** (`Upgrades/ISkillTreeService.cs`) — the shared contract (`Tree`, `IsPurchased`, `IsRevealed`, `IsTeased`, `GetCost`, `CanPurchase`, `TryPurchase`, `OnTreeChanged`) both `SkillTreeService` and `ReincarnateService` implement, so `SkillTreeView`/`SkillNodeView` can render either tree without knowing which currency it spends. **UI shows `GetCost(node)`, never `node.cost` directly** — `GetCost` is where the family price ladder lives (both services implement the same rule).
- **`SkillTreeService`** (`Upgrades/SkillTreeService.cs`) — scene **singleton** (`Instance`). Owns purchase logic (`TryPurchase` spends gold via `Wallet.TrySpend`, applies the node's `effects` to `PlayerStats`), reveal/affordability queries, and **persistence**: purchased node ids live in `SaveData.purchasedNodeIds` and are **re-applied on every run** in `Start`, making upgrades permanent meta-progression like gold — until a Reincarnate wipes them (see below). Raises `OnTreeChanged`.
- **`SkillTreeView` / `SkillNodeView`** (`UI/`) — render a tree (driven by any `ISkillTreeService`) on a canvas: lay out nodes at their CSV coords (with `contentPadding` breathing room around the tree), draw prereq connectors, mark state on each node (border tint + tick on owned, padlock on teased), buy on click, refresh on `OnTreeChanged`/`Wallet.OnCoinsChanged`. `SkillNodeView.costSuffix` labels the currency (blank for gold, e.g. `" pts"` for Reincarnate).
- **`SkillTreeCsvEditorWindow`** (`Editor/SkillTreeCsvEditorWindow.cs`) — editor window (**Bladehold > Skill Tree Editor**) for editing a `SkillTreeSO`'s CSV in-Editor: list + detail node editing, add/duplicate/delete rows, and drag-and-drop Sprite icon assignment (dropping a sprite sets the node's icon name **and** adds it to the SO's `icons` list). "Save CSV" writes the file back through `AssetDatabase` and calls `tree.Reload()`, so parse errors surface immediately.

How stats reach gameplay: **`DamageTrigger`** (with `readsPlayerStats` on) pulls effective sword damage/range/cut-through-cap from `PlayerStats`, rolls crits (`baseCritMultiplier` 1.5 is the `CritMultiplier` stat base; the "Critical Damage" skill line raises it to 2×/4×/8×), applies the charge multiplier (and scales knockback by `1 + ChargeLevel × ChargeKnockbackBonus` — the "Amplified Knockback" line), and stamps `knockbackForce`/`sourcePosition` onto the `Damage`; with `readsPlayerStats` off (e.g. the Death Nova hitbox) it instead uses its own serialized `knockbackForce`. **`KnockbackReceiver`** (on goblins) reacts to `Health.OnDamaged` to shove the `NavMeshAgent` — it skips the slide when the same hit knocks an enemy down or flings it (`ImpulseReceiver.IsIncapacitated`/`WouldIncapacitate`), so the two reactions never fight over one hit. **`PlayerAttack`** times the Synty `InputReader` attack hold in discrete charge levels — each level takes another `chargeTimePerLevel` second of holding, capped at `StatType.MaxChargeLevels` (base 0 = hold-to-charge locked until the "Heavy Strike" node is bought), and `AttackDamageMultiplier = 1 + ChargeLevel × ChargeDamageBonus` — exposing a live `AttackDamageMultiplier`/`IsCharging`/`ChargeLevel`, which **`SwordChargeFeedback`** polls to escalate charge VFX/SFX. **`PlayerMoveSpeedBinder`** scales the Synty controller's private speed fields by reflection. `SaveSystem` caches a single shared `SaveData` so `Wallet`, `SkillTreeService`, and `ReincarnateService` don't clobber each other on save.

### Analytics (`Analytics/`)
- **`RunTelemetry`** (`Analytics/RunTelemetry.cs`) — balance telemetry, writing **one CSV per run** to `persistentDataPath/Telemetry/` (path logged to the console at run start). **Self-bootstrapping** via `[RuntimeInitializeOnLoadMethod]` — nothing to add to the scene; it survives scene reloads (`DontDestroyOnLoad`) and re-binds to the new scene's singletons on `sceneLoaded`, starting a new file per run. A pure listener (never changes gameplay): wave rows from `WaveSpawner.WaveStarted`/`WaveCleared` + `GameStats` diffs, damage taken from the player's `Health.OnDamaged`, damage dealt/crits from the sword `DamageTrigger.OnHit` (found via the `ReadsPlayerStats` accessor), quick-vs-charged swings from `InputReader.onAttackDeactivated` + `PlayerAttack.ChargeLevel`, sprint seconds by polling the Synty controller's private `_isSprinting` by reflection (the `PlayerMoveSpeedBinder` precedent), and purchases from both tree services' **`OnNodePurchased(SkillNode, int pricePaid)`** event (added alongside `OnTreeChanged`; the int is the ladder price actually paid). Row types: `run_start` (saved-progress context), `wave_clear`, `purchase`, `death` (fatal wave partials), `run_summary` (totals). Rows are appended immediately so data survives quitting mid-run; every missing dependency degrades to a one-line warning.

### Reincarnate (`Reincarnate/`)
A second, permanent meta-progression currency ("Reincarnate Points") layered on top of the gold tree. From the death screen, the player can *reincarnate*: banking points and resetting the gold skill tree + wave counter to 1, while keeping every Reincarnate-tree upgrade forever.
- **`ReincarnateService`** (`Reincarnate/ReincarnateService.cs`) — scene **singleton** (`Instance`), implements `ISkillTreeService` against its own `SkillTreeSO` (pointed at `Config/Reincarnate.csv`), spending/persisting `SaveData.reincarnatePoints`/`purchasedReincarnateNodeIds` instead of gold. `PreviewPointsForReincarnate()` reads `WaveSpawner.Instance.CurrentWave` (points earned = highest wave reached this run). `Reincarnate()` banks those points, clears `SaveData.purchasedNodeIds` (so `SkillTreeService.Start()` naturally comes back empty next run), sets `RunState.StartingWave = 1`, and reloads the scene — it never touches its own purchased-node list, since the point tree is meant to persist.
- Starter Reincarnate nodes (`Config/Reincarnate.csv`): **Death Nova** (`DeathNova`/`DeathNovaSO`, see Player above), **Golden Goblin** (`GoldenGoblin`, see Enemies above), and **Grave Robber** (`GoldOnDeathCollector`, see Player above) — each a small independent branch, stacking 2-4 tiers deep.

## Conventions observed in this codebase

- **`Health` is the hub; dependencies point inward.** `Health` raises `OnDied` (once) and `OnDamaged(Damage)` and knows nothing about its listeners. Reactive behaviour (death animation, stopping movement/attacks, disabling colliders, dropping loot, scoring, damage numbers, UI, wave tracking) lives in separate components that **subscribe** to those events. When adding a reaction to damage or death, add a listener — don't reach into `Health`. Always **unsubscribe in `OnDestroy`**. The one exception is **`TryPreventDeath`**, an `event Func<bool>` checked right before a lethal hit latches — a handler that wants to *cancel* death (not just react to it), like `DeathNova`'s revive, returns `true` and calls `Health.Revive` itself. Its sibling **`TryBlockDamage`** (an `event Func<Damage, bool>`, checked before any health is lost) is the equivalent for negating a hit entirely, used by `DamageBlocker`. The third sibling, **`ScaleDamageTaken`** (an `event Func<Damage, float>`, checked after `TryBlockDamage` and before health is lost), *shapes* damage rather than cancelling it: each handler returns a multiplier, all handlers' returns multiply together (clamped ≥ 0), and `Damage.value` is scaled in place so every `OnDamaged` listener (damage numbers, telemetry, knockback) sees the mitigated value — used by the Berserker's `RageBuff` damage reduction. These three are the only hooks that can alter what `Health` does; everything else stays a normal reactive listener.
- **Death is signalled, not destruction.** Dead enemies become corpses (colliders disabled, death/cheer animation). Detect death via `Health.OnDied` / `Health.IsDead`, **never** via `OnDestroy` or object-count. Corpses do eventually despawn — `CorpseDespawner` sinks and destroys them after `CorpseConfigSO.corpseLifetime`, with `CorpseManager` capping how many linger — but that is long after every `OnDied` listener has reacted; no logic may depend on a corpse's destruction.
- **Validate dependencies in `Start`.** Auto-wire sibling/serialized references in `OnValidate` (`GetComponent<…>()`, or `GetComponentInChildren<Animator>()` since Synty rigs keep the Animator on a child), then in `Start` null-check, `Debug.LogError`, and set an `anyError` flag; `Update`/handlers early-return `if (anyError)`. Follow this for any new component.
- **Scene singletons**: `Player.Instance`, `GameStats.Instance`, `WaveSpawner.Instance` — assigned in `Awake`, cleared in `OnDestroy`, and they reset naturally on scene reload. Reach other objects through these rather than `FindObjectOfType`.
- **Tunables go on a `ScriptableObject`** (`*SO`, `[CreateAssetMenu]` under `Scriptable Objects/…`). Components read shared config from an asset rather than per-instance fields. Tune behaviour by editing the asset, not the script.
- **Numbers that might plausibly become upgrade-modifiable are registered as `StatType` bases, not hardcoded literals** — even when the current value is 0/off (e.g. `GoldenGoblinChance` starts at 0 until a Reincarnate node raises it; `DeathNovaCharges` starts at 0 to mean "locked"). This mirrors the existing `SwordDamage`/`MoveSpeed` pattern: whichever system owns the value registers the base via `PlayerStats.SetBase` and reads it back via `GetValue`, so any future skill/Reincarnate node can layer a modifier on top without that system's code changing at all.
- **Animator integration by trigger name**: death/cheer/attack states are driven by string triggers (`Death`, `Cheer`, `Attack`) hashed in `Start`; timing-critical hits use either a tuned wind-up delay or a Unity animation event routed through `AnimationEvents`.
- **Persistence has two tiers**: cross-run progress (gold) goes through `SaveSystem`/`SaveData` to disk; within-session run state that must survive a scene reload (current wave) goes in a static like `RunState`. Restarting = `SceneManager.LoadScene` of the active scene, which resets scene singletons.
