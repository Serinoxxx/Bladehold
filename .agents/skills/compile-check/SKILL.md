# Compile-check C# without the Unity Editor

There is no CLI build script, and the Editor may be closed or busy. Verify C# with:

```
dotnet build Assembly-CSharp.csproj
```

from the project root (`C:\Users\lance\source\repos\My project`). Editor-only scripts (anything under an `Editor/` folder) compile in `Assembly-CSharp-Editor.csproj` instead — build that one too if you touched them. Builds take ~10–25s against the Unity-install DLL references.

## The trap: new files are silently skipped

The csprojs are **generated by Unity** and list source files explicitly. Any `.cs` file created since Unity last regenerated them is **not in the csproj — the build "succeeds" without compiling it**, so a green build proves nothing about new files.

For every file you created this session:

1. Check it's listed: `grep "MyNewFile.cs" Assembly-CSharp.csproj`
2. If absent, insert a line next to an existing sibling `<Compile Include=...>` entry (note the **backslash** paths):
   ```xml
   <Compile Include="Assets\Bladehold\Bladehold Scripts\Player\MyNewFile.cs" />
   ```
3. Rebuild.

This temporary hand-edit is safe despite CLAUDE.md's "don't hand-edit generated csprojs" rule — that rule means *don't treat them as durable*; Unity overwrites them on its next refresh anyway. Do **not** commit csproj/slnx changes; they're not tracked deliverables. If the Editor is open in the background it auto-regenerates csprojs and creates `.meta` files for new scripts on focus.

## Interpreting results

- Fix every **error**; ignore pre-existing warnings you didn't introduce.
- A clean build proves syntax/API correctness only — behaviour still needs Play-mode verification, which belongs in the TODO.md manual-verification checklist (`/editor-wiring-todo`).

Run this before writing the TODO entry and before every commit.
