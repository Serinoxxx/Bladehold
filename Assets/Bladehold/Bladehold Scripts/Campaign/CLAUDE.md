# Campaign

The macro run structure: a 10-tier branching node map between the Meta Area and the battles.

## Pieces

- **`CampaignGraphSO`**: the graph. **Source of truth is the asset** `Assets/Bladehold/Resources/CampaignGraph.asset`, with one node asset per node in `Resources/CampaignNodes/`. `CampaignManager.ActiveGraph` loads it via `Resources.Load("CampaignGraph")`, and the map scene references it directly. It's generated by `Editor/SetupCampaignPrefabsAndAssets.cs` (**Bladehold/Campaign/Setup All Campaign Prefabs & Scene**) from `BuildDefaultGraph()`. After generation, tweak nodes in the inspector; the setup menu asks before regenerating over them. There is no runtime fallback graph: a missing asset is a `Debug.LogError` (`CreateDefaultCampaignGraph()` is only for editor tests).
- **`CampaignNodeSO`**: one node. `nodeId`, `sceneName`, `nodeType`, `tierIndex`, `mapPosition`, `captainName`, `difficultyTier` (Standard/Enraged/Nightmare/Omega), `bountyType`, gold/blood/metal rewards, `nextNodes`, `endsCampaign`. `EndsCampaign` is true when `endsCampaign` is ticked or the node has no next nodes (the two final bosses). The demo cutoff does **not** use it: see "Demo cutoff" below.
- **`CampaignNodeType`**: Combat, RestArea, SupplyRoom (unused, kept for serialization), FishingPond, PreBoss, NecromancerEncounter, PrincessBoss, NecromancerBoss.
- **`CampaignManager`**: `DontDestroyOnLoad` singleton (auto-creates if missing). Holds current/completed/available node ids, mirrored into `RunSession.Campaign*` so they survive scene loads. `SelectNode` loads the node's scene (resetting `RunSession.CurrentWave = 1` for Combat/PreBoss). `CompleteCurrentNode` makes **only** that node's `nextNodes` available (every other open node closes: no backtracking), records it as `LastCompletedNodeId` (the map's "you are here", exposed as `CurrentLocationNode`, root before any clear), pays gold into the run and blood/metal straight to `SaveData`. **Every node exit goes through `CompleteCurrentNodeAndContinue()`**: back to the map, or `EndCampaign()` (run wiped, Meta Area) if the node ends the campaign. Use `CampaignManager.HasInstance` in teardown code so you don't auto-create a manager while unloading.
- **`CampaignMapUI`**: campaign logic plus the overlay UI. Instantiates one `CampaignNodeButton.prefab` label per node into a full-screen overlay and, every `LateUpdate`, hangs it under its castle (projected from the diorama site's label anchor). Pushes node/route status into the diorama and pans its camera for focus. A missing prefab, container, graph or diorama is a `Debug.LogError` and an empty map, never a code-built fallback. Starts a new campaign run on first open (`!RunSession.IsCampaignRun`).
- **Diorama (`Diorama/`)**: the map is a generated 3D miniature. `CampaignDiorama` (scene root) indexes one `CampaignDioramaSite` per node (mini castle: banners recoloured horde red / liberated blue, greyed when bypassed or demo-locked, pulsing ring when open) and one `CampaignDioramaRoad` per edge (dashed glow overlay). `CampaignDioramaCamera` pans along X (drag / wheel; a drag swallows the click that ends it; with a pad there is no free pan, it just follows the focused node). Runtime tunables are on `Config/Campaign/CampaignDioramaLook.asset`. Each node's landscape is `CampaignBiome` (`CampaignNodeSO.mapBiome`, `Auto` = guessed from the scene by `CampaignBiomes.Resolve`).
- **Generated, never hand-edited:** **Bladehold > Campaign > Build Map Diorama** (`Editor/CampaignDiorama/CampaignDioramaBuilder.cs`) builds the terrain (vertex-coloured, flat-shaded, `Bladehold/Diorama Vertex Lit`), plinth, ponds, roads, castles (`MiniCastleBuilder`), procedural trees (`DioramaFlora`), Synty scatter, light/post and camera from the graph + `Config/Campaign/CampaignDioramaTheme.asset`. It then reshapes the node prefab and canvas (`CampaignDioramaUIRig`). Meshes go to `Config/Campaign/CampaignDioramaMeshes.asset`. Change the graph or theme and rebuild. Delete the theme asset to regenerate it from `CampaignDioramaDefaults`.
- **Level previews:** **Bladehold > Campaign > Capture Level Previews** (`CampaignPreviewCapture`) opens each node's scene, renders a hero shot (pose from `Config/Campaign/CampaignPreviewShots.asset`, else behind and above the player spawn) into `Bladehold Images/Campaign Previews/` and sets `CampaignNodeSO.previewImage`, which the tooltip shows. The open scene must be saved first. Close the Synty Sidekick window before saving scenes: it injects a `Combined Character` into the active scene.
- **`CampaignNodeButtonUI` / `CampaignTooltipUI`**: button visuals and hover tooltip. Clicks come only via the `Button` (no `IPointerClickHandler`, which double-deployed).

## Flow

- **Root: the Valley Stronghold** (`tier1_valley_stronghold`, plan 21) is also the tutorial's last scene (T3). `Tutorial/TutorialSceneMode` picks its mode before any Awake: a campaign deploy (`RunSession.CampaignCurrentNodeId` set) switches off the tutorial objects and uses `ValleyStrongholdRoundPacingConfig`; anything else (arriving from T2, or opened in the Editor) runs the tutorial. Tutorial victory → `CampaignManager.StartCampaignRunFromTutorial()`: the run carries on with the root already cleared. It sits in its own map column (tier 0, "The Valley", no numeral) left of the Alpine Keep, at threat 1.
- Meta `BattlePortal` → `RunSession.StartNewRun` + `CampaignManager.StartCampaignRun` → map. The map has no Return-to-Meta button: the only ways home are death or campaign end.
- Sector victory → `DeathScreen.ShowVictory` → `CampaignManager.CompleteCurrentNodeAndContinue()`. If the current node ends the campaign, `ShowVictory` shows the campaign-complete title/button instead. A battle scene played straight from the Editor has no campaign run, so its victory starts a fresh one and opens the map.
- Rest Area in campaign mode: `RestAreaGate` saves HP ratio + ultimate charge, then continues.
- Fishing: `FishingManager.CommitRewardsAndReturnToCampaign` continues the same way (through the loading screen).
- Each Combat node supplies only `difficultyTier`, `bountyType` and `captainName` to `GameLoopManager`. Wave count and pacing are the same everywhere; scaling with depth is planned (see root CLAUDE.md, "Design direction").

## Demo cutoff

`DemoConfigSO.campaignCutoffTier` (4). Nodes past it never enter `AvailableNodeIds` and render as `NodeVisualStatus.DemoLocked`. Clearing any cutoff-tier node returns to the map as normal; `CampaignManager.IsDemoEndReached` then makes `CampaignMapUI` show `DemoEndScreenUI` (Thanks/Wishlist), whose Continue calls `EndCampaign()`. Sector victory screens therefore still say "Proceed to Campaign Map".

## Bosses (tier 8)

- The Crypt node (`tier8_crypt_sanctum`) loads `Bladehold Necromancer Crypt`. `NecromancerConfrontationUI` opens itself on scene start (`openOnSceneStart`, `boss` auto-found) and offers:
  - **Obey**: `EnterBranchNode("tier8_princess_boss", loadScene: true)` completes the Crypt node and deploys to the Princess Sanctuary.
  - **Defy**: `EnterBranchNode("tier8_necromancer_boss", loadScene: false)` completes the Crypt node and makes the Necromancer node current; the fight stays in the Crypt scene.
- Boss death → `DeathScreen.ShowVictory()` (campaign-complete mode, since boss nodes have no next nodes) → button → `CompleteCurrentNodeAndContinue()` → `EndCampaign()`. Boss scenes need a `DeathScreen` instance; without one the boss logs an error and ends the campaign directly.

## Map UI status

- **Layout:** 10 tiers; column x = 140 + 260 × (tier − 1). `tierIndex` is the column, the sector threat (`SectorThreat`) and the demo gate all at once. Tiers 1-4 are the demo (plus the tier-0 Valley Stronghold column before them): every route out of the Alpine Keep ends on the Graveyard (tier 4 = `DemoConfig.campaignCutoffTier`); the tier-2 stops skip column 3 and run straight to it. Elsewhere a node links only to the nearest lanes of the next tier, so paths never cross, and the lanes rejoin at the Graveyard, the Great Hall (tier 6), the Throne Antechamber (tier 9) and the Crypt. Keep new nodes to that rule (edit the asset and `BuildDefaultGraph()` together). Stop rules: a battle (Combat, PreBoss, Crypt, bosses) may lead to anything, but a shop (RestArea) or a FishingPond must always lead to a battle, so you never get two stops in a row.
- **Statuses:** Completed, Available (children of the current location), Locked (still reachable later, no padlock), Bypassed (unreachable from here: faded), DemoLocked (padlock). The "you are here" flag (`CampaignMapUI.locationMarker`) and the tier column headers (`CampaignTierHeader.prefab`, which slide with their column as the camera pans) live under `MapOverlay`, outside `NodesContainer`, which is cleared on every rebuild.
- `mapPosition` becomes world X/Z at `CampaignDioramaThemeSO.worldPerMapUnit` (1/32: tiers about 8 units apart). The node prefab's pivot sits where its plaque meets the castle's front edge.
- The map unlocks the cursor itself (`CursorLockManager`, owner `CampaignMap`). Keyboard/gamepad focus is custom in `CampaignMapUI.Update` (WASD/arrows/d-pad/stick step to the nearest node in that direction, measured on the map ground plane within a `navMaxAngle` cone; Enter/Space/E/pad A deploys), not EventSystem selection, because locked nodes are non-interactable Buttons and could never be selected. Hovering with the mouse moves the focus (ignored while the pad is active, so a parked cursor can't steal it). The inspected node's castle gets a runtime-built highlight (`CampaignDioramaSite.SetInspected`: pulsing ring + light column; tunables on the look asset).
- Campaign progress isn't saved to disk; quitting mid-run loses it.
